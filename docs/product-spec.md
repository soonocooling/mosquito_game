# 모기 피하기 (못 함)

> 가칭. 제품명은 [결정] — 확인 필요.

## 한 줄 소개
링크를 받은 친구가 웹캠 앞에서 모기를 피하려 발버둥 치다 얼굴이 퉁퉁 부어버리는, 절대 이길 수 없는 모션 인식 웹 게임.

## 사용자와 사용 맥락
- 주 사용자: 링크를 전달받은 친구 (사전 설명 없이 첫 진입)
- 사용 빈도·시점: 1회성, 1~3분 플레이. 메신저에서 링크 클릭 직후
- 사용 환경: **스마트폰 세로 화면 + 전면 카메라가 1순위** [명시], 노트북/데스크톱 웹캠 2순위. 브라우저 단독 동작, 1인 플레이
- 모바일 자세: 한 손으로 폰을 들거나 거치한 상태. 폰을 든 경우 잡기에 쓸 수 있는 손은 1개 [추론]
- 사용자 수 규모: 동시 접속 제한 없음 — 모든 연산이 사용자 기기에서 수행되므로 서버 부하가 없다 [추론]

## 화면 구조
```
S-1 랜딩 ──(시작 버튼 → 카메라 권한 허용)──▶ S-3 로딩 ──▶ S-4 게임 ──(그만하기)──▶ S-5 결과
   │                                                         ▲                      │
   └──(권한 거부/카메라 없음)──▶ S-2 권한 안내 ──(재시도)──────┘                      └──(다시 하기)──▶ S-4
```
- S-1 랜딩: 제목, 한 줄 설명("모기를 피해봐"), 시작 버튼. 카메라 권한은 버튼 클릭 시점에 요청
- S-2 권한 안내: 권한 거부/카메라 미탐지 시 원인별 안내와 재시도 버튼
- S-3 로딩: 인식 모델 다운로드·초기화 진행률
- S-4 게임: 좌우 반전된 웹캠 영상 + 부기 필터 + 모기 + HUD(물린 횟수, 잡은 수, 현재 모기 수, 경과 시간). 세로 9:16 기준 레이아웃
- S-R 회전 안내(오버레이): 모바일에서 가로로 돌리면 게임 일시정지 + "세로로 돌려줘" 표시, 세로 복귀 시 재개
- S-5 결과: 최종 통계 + 마지막 얼굴 캡처 [결정]

## 기능 명세

### A. 카메라·인식

### F-01 웹캠 입력과 상반신 화면 구성 (세로 모바일 우선)  [명시]
**동작**: 시작 버튼을 누르면 전면 카메라 영상이 전체 화면에 거울 모드로 표시된다.
**세부 요구사항**:
- 모바일: `getUserMedia({ video: { facingMode: 'user', width: { ideal: 720 }, height: { ideal: 1280 }, aspectRatio: { ideal: 9/16 } } })`, 데스크톱: 1280×720
- 실제 스트림 크기는 요청과 다를 수 있으므로(iOS는 가로 크기로 반환하기도 함) 항상 `video.videoWidth/videoHeight`로 크롭·좌표 변환 계산
- `<video playsinline muted autoplay>` 필수 (iOS 전체화면 재생 방지)
- 레이아웃: `height: 100dvh`, `env(safe-area-inset-*)`로 노치·홈 인디케이터 회피, `touch-action: none`·`overscroll-behavior: none`으로 스크롤·줌·당겨서 새로고침 차단
- 방향: iOS는 화면 방향 고정 API가 없으므로 `matchMedia('(orientation: landscape)')` 감지 시 S-R 오버레이 + 게임 일시정지
- 화면 꺼짐 방지: 게임 중 `navigator.wakeLock.request('screen')`, 미지원 시 무시
- 탭 전환·앱 이탈(`visibilitychange`) 시 일시정지, 복귀 시 카메라 트랙이 끊겼으면 재요청
- 영상은 좌우 반전 표시. 모든 인식 좌표도 `x' = 1 − x`로 반전해 화면 좌표와 일치시킨다
- 화면비가 다르면 `object-fit: cover` 방식으로 잘라내고, 잘린 영역을 좌표 변환에 반영
- 얼굴 폭이 화면 폭 대비 25% 미만이면 "좀 더 가까이", 60% 초과면 "폰을 조금 멀리 — 손이 보이게" 안내 [결정]. 세로 화면에서 상반신과 손이 함께 들어오려면 폰을 팔 길이 정도로 떨어뜨려야 한다
- HTTPS에서만 동작 (getUserMedia 제약) [추론]
**완료 조건**:
- [ ] 버튼 클릭 후 1회의 권한 팝업만 뜬다
- [ ] 사용자가 오른손을 들면 화면 오른쪽 손이 올라간다
- [ ] 권한 거부 시 S-2로 이동하고, 재시도 버튼으로 다시 요청된다
- [ ] 카메라가 없는 기기에서 S-2에 "카메라를 찾을 수 없음"이 표시된다
- [ ] iPhone Safari·Android Chrome 세로 화면에서 영상이 검은 여백·찌그러짐 없이 화면을 채운다
- [ ] 게임 중 폰을 가로로 돌리면 모기가 멈추고 안내가 뜨며, 세로로 돌리면 그대로 이어진다
- [ ] 2분간 화면을 건드리지 않아도 화면이 꺼지지 않는다 (Wake Lock 지원 기기)

### F-02 얼굴 추적  [추론]
**동작**: 매 프레임 얼굴의 위치와 표면 랜드마크를 추적한다. 모기의 목표 지점과 부기 위치가 모두 이 랜드마크에 고정된다.
**세부 요구사항**:
- 얼굴 랜드마크 모델(MediaPipe Face Landmarker, 478점)로 1인 추적 — 기술 선택 근거는 「구현 방향」 참조
- 얼굴 크기 기준값 `faceW` = 좌우 광대 랜드마크 간 거리. 모기 속도·부기 반경 등 모든 길이는 `faceW` 단위로 정규화 (카메라 거리와 무관하게 같은 체감)
- 떨림 제거: One Euro Filter로 랜드마크 평활화
- 얼굴 소실 시(손으로 가림, 화면 밖): 마지막 자세를 500 ms 유지 후 "얼굴 어디 갔어?" 표시, 모기는 화면 중앙 부근 배회
- 얼굴 재등장 시 기존 부기는 그대로 유지
**완료 조건**:
- [ ] 고개를 좌우로 45° 돌려도 코끝 마커가 코에서 벗어나지 않는다
- [ ] 손으로 얼굴을 1초 가렸다 떼도 부기가 사라지지 않는다
- [ ] 카메라에서 멀어져도 모기 크기·부기 크기가 얼굴 비율로 유지된다

### F-03 손 추적  [추론]
**동작**: 양손의 위치·속도·쥠 상태를 추적해 모기 잡기(F-08) 판정에 사용한다.
**세부 요구사항**:
- 손 랜드마크 모델(MediaPipe Hand Landmarker, 손당 21점), 최대 2손
- 손바닥 중심 = 랜드마크 0, 5, 9, 13, 17의 평균. 손바닥 반경 `palmR` = |p0 − p9| × 0.8
- 손 속도 = 최근 100 ms 손바닥 중심 이동량의 이동평균 (단위: faceW/s)
- 쥠 정도 = 손끝(4, 8, 12, 16, 20)~손목(0) 평균 거리 / |p0 − p9|
- 성능 확보를 위해 손 추론은 얼굴 추론과 번갈아 실행 가능 (F-12 기준 미달 시)
**완료 조건**:
- [ ] 손을 빠르게 휘두르면 디버그 모드에서 속도 값이 임계값을 넘는 것이 보인다
- [ ] 손이 얼굴 앞을 지나가도 얼굴 추적이 500 ms 이내 복구된다

### B. 모기

### F-04 모기 추적 비행  [명시]
**동작**: 모기가 사용자의 얼굴을 따라다닌다. 사용자가 움직이면 경로를 바꿔 계속 쫓아온다.
**세부 요구사항**:
- 각 모기는 얼굴 랜드마크 중 하나를 목표로 선택: 이마(10), 코끝(1), 턱(152), 좌우 볼(50, 280), 좌우 윗눈꺼풀(159, 386), 입술 위(0) — 인덱스는 예시, 구현 시 실측 확인
- 조향 행동(steering): `가속 = normalize(목표 − 위치) × maxSpeed − 속도`, 최대 가속 제한
- 예측 추적: 목표 위치 = 현재 랜드마크 + 얼굴 속도 × 0.15 s (도망가는 방향을 앞질러 감)
- 비행감: Perlin noise로 좌우 흔들림 추가 (진폭 0.05 faceW)
- 모기 크기: 0.06 faceW, 날개 2프레임 애니메이션 [결정]
- 모기끼리 겹침 방지: 반경 0.08 faceW 내 분리(separation) 힘
**완료 조건**:
- [ ] 얼굴을 화면 왼쪽 끝으로 옮기면 모든 모기가 그쪽으로 이동한다
- [ ] 모기 50마리가 있어도 한 점에 뭉쳐 보이지 않는다

### F-05 "피할 수 없음" 보장  [명시]
**동작**: 사용자가 아무리 빨리 움직여도 모기는 결국 도달해서 문다.
**세부 요구사항**:
- `maxSpeed` = 3.0 faceW/s 기본, 목표와의 거리에 비례해 증가 (거리 2 faceW 이상이면 최대 8 faceW/s)
- 접근 시간 보장: 접근 상태가 4 s를 넘으면 0.3 s 동안 순간 가속(속도 상한 해제) → 도달
- 얼굴이 화면 밖으로 나간 경우는 예외 (F-02 규칙 적용)
**완료 조건**:
- [ ] 머리를 계속 좌우로 흔들어도 첫 물림이 6 s 이내 발생한다
- [ ] 가만히 있을 때보다 움직일 때 물림 간격이 2배 이상 늘어나지 않는다

### F-06 무는 동작  [명시]
**동작**: 모기가 얼굴에 착지해 잠시 붙어 있다가 물고 날아간다.
**세부 요구사항**:
- 상태 머신: `APPROACH → LANDED(0.8 s) → BITE → FLY_OFF(0.6 s) → COOLDOWN(2~4 s 랜덤) → APPROACH(새 목표 선택)`
- LANDED 동안 모기는 목표 랜드마크 + 오프셋 위치에 고정 (얼굴과 함께 움직임)
- BITE 순간: F-07 부기 추가, HUD 물린 횟수 +1, 짧은 화면 흔들림(80 ms) [결정]
- LANDED 중 잡히면(F-08) 물림은 발생하지 않는다
**완료 조건**:
- [ ] 모기가 볼에 앉은 상태에서 고개를 돌리면 모기가 볼에 붙은 채 따라온다
- [ ] 물림 1회당 물린 횟수가 정확히 1 증가한다

### F-07 물린 부위 부기 필터  [명시]
**동작**: 물린 자리가 빨갛게 부풀어 오르고, 물릴수록 누적되어 얼굴 전체가 퉁퉁 붓는다.
**세부 요구사항**:
- 부기(Bite)는 화면 좌표가 아니라 **랜드마크 인덱스 + 얼굴 로컬 오프셋**으로 저장 → 얼굴을 움직여도 부기가 피부에 붙어 다닌다
- 렌더링: WebGL 프래그먼트 셰이더 한 패스에서 볼록 왜곡(bulge) + 붉은 기 처리
  - 각 부기 i: 중심 cᵢ, 반경 Rᵢ, 세기 sᵢ
  - r = |uv − cᵢ| / Rᵢ, r < 1이면 `k = sᵢ(1 − r²)²`, 샘플 좌표 `uv_s = cᵢ + (uv − cᵢ)(1 − k)` (중심부 확대 = 부풀어 보임)
  - 붉은 기 `red += k`, 최종 색 = `mix(c, c·(1.0, 0.55, 0.55) + (0.15, 0, 0), clamp(red, 0, 0.8))`
  - 가장자리에 약한 광택 하이라이트 [결정]
  - 좌표는 화면비 보정 후 계산
- 누적 규칙:
  - 새 물림이 기존 부기 중심에서 0.5 R 이내 → 병합: s += 0.15 (상한 0.6), R ×= 1.1 (상한 0.5 faceW)
  - 아니면 신규 부기: R = 0.12 faceW, s = 0.25
  - 셰이더 uniform 상한 32개. 초과 시 가장 가까운 두 부기를 병합
- 등장 애니메이션: 0 → 목표 세기까지 600 ms, 살짝 초과했다가 되돌아옴(overshoot)
- 부기는 게임 중 줄어들지 않는다 [결정 — 확인 필요]
**완료 조건**:
- [ ] 한 번 물리면 1 s 이내 해당 부위가 붉고 볼록해진다
- [ ] 같은 볼을 5번 물리면 1번 물렸을 때보다 눈에 띄게 크다
- [ ] 물린 뒤 고개를 돌려도 부기가 원래 자리(피부)에 남아 있다
- [ ] 물림 50회 이후에도 F-12 프레임 기준을 만족한다

### F-08 손으로 모기 잡기  [명시]
**동작**: 손으로 모기를 치거나 잡으면 모기가 죽는다.
**세부 요구사항**:
- 판정 방식 (셋 중 하나라도 만족) [결정 — 확인 필요]
  1. **스윙**: 모기가 손바닥 원(`palmR + 모기반경`) 안 & 손 속도 > 1.5 faceW/s
  2. **박수** (폰 거치 시에만 가능): 두 손바닥 거리가 150 ms 안에 50% 이상 줄어 0.6 faceW 미만 & 모기가 두 손바닥 사이 선분 근처(0.3 faceW 이내)
  3. **움켜쥐기**: 모기가 손바닥 원 안 & 쥠 정도가 200 ms 안에 1.8 → 1.1 미만으로 감소
  4. **화면 탭** (모바일 대체 입력) [결정]: 터치 지점 반경 0.12 faceW 안의 모기 처치. 폰을 든 손 엄지로 사용
- 세로 화면에서는 손이 화면 밖으로 나가기 쉬우므로 스윙 판정은 손이 부분적으로만 보여도(랜드마크 신뢰도 0.5 이상) 인정
- 손이 느리게 모기 위를 지나가는 것만으로는 죽지 않는다
- 판정은 매 프레임 이전·현재 손 위치를 잇는 선분 기준(빠른 손이 모기를 건너뛰는 문제 방지)
- 한 번의 동작으로 여러 마리 동시 처치 가능
- 분열 직후 무적 모기(F-10)는 판정에서 제외
**완료 조건**:
- [ ] 손바닥으로 모기를 빠르게 치면 죽는다
- [ ] 손을 모기 위에 천천히 올려두면 죽지 않는다
- [ ] 모기 앞에서 박수를 치면 죽는다
- [ ] 모기를 움켜쥐면 죽는다
- [ ] 모바일에서 모기를 손가락으로 탭하면 죽는다
- [ ] 폰을 한 손에 든 채 반대 손 스윙만으로 모기를 잡을 수 있다

### F-09 피 튀김 효과  [명시]
**동작**: 잡힌 자리에서 피가 짧게 튀고 모기가 사라진다.
**세부 요구사항**:
- 파티클 12~20개, 랜덤 방향 초속 1~3 faceW/s, 중력 적용, 수명 400 ms
- 바닥 자국(splat) 스프라이트 1개, 1.5 s 동안 페이드아웃 [결정]
- 짧은 "찰싹" 효과음 [결정]
- 동시 파티클 상한 500개, 초과 시 오래된 것부터 제거
**완료 조건**:
- [ ] 처치 순간 피 파티클이 보이고 2 s 후 흔적이 완전히 사라진다

### F-10 분열  [명시]

## 인식 기술 선택지

**권장: A.** 이 게임의 핵심 두 기능(피부에 붙는 부기, 손으로 잡기)이 모두 랜드마크를 요구한다. B는 둘 다 직접 만들어야 하고 품질이 낮으며, C는 "링크 클릭 즉시 플레이"와 비용·프라이버시에서 불리하다. OpenCV를 반드시 쓰고 싶다면 A 위에 OpenCV.js를 "화면 움직임량(프레임 차분)" 계산용으로 얹어, 움직임이 클수록 모기가 흥분해 빨라지는 연출 등에 쓰는 구성이 현실적이다.

## 부기 셰이더 골격
```glsl
#version 300 es
precision highp float;
uniform sampler2D uVideo;
uniform vec4 uBites[32];   // xy: 중심(uv), z: 반경, w: 세기
uniform int uCount;
uniform float uAspect;
in vec2 vUv; out vec4 o;
void main() {
  vec2 uv = vUv; float red = 0.0;
  for (int i = 0; i < uCount; i++) {
    vec2 d = uv - uBites[i].xy; d.x *= uAspect;
    float r = length(d) / uBites[i].z;
    if (r < 1.0) {
      float k = uBites[i].w * pow(1.0 - r*r, 2.0);
      d *= (1.0 - k); d.x /= uAspect;
      uv = uBites[i].xy + d;
      red += k;
    }
  }
  vec3 c = texture(uVideo, vec2(1.0 - uv.x, uv.y)).rgb;   // 거울 반전
  vec3 swollen = c * vec3(1.0, 0.55, 0.55) + vec3(0.15, 0.0, 0.0);
  o = vec4(mix(c, swollen, clamp(red, 0.0, 0.8)), 1.0);
}
```
부기 좌표 갱신: 매 프레임 `center = landmark[anchorIdx] + R_face · localOffset · faceW` (R_face는 양 눈 랜드마크로 구한 2D 회전).
